# 基于多模态数据融合的水体浊度预测系统 V1.0 软件规格说明

本文件由 `G:\AI4S\基于多模态数据融合的水体浊度预测系统V1.0_软著说明书(1).docx` 结构化整理得到，目标不是保留软著格式，而是转成下一位助手可以直接理解和执行的软件规格说明。

## 1. 软件定位

- 软件名称：基于多模态数据融合的水体浊度预测系统
- 版本号：V1.0
- 软件类型：数据处理、智能预测与水环境辅助分析软件
- 运行模式：以 B/S 架构为主，支持服务端集中部署与浏览器端访问

软件面向河口、湖泊、河道及近岸水域的浊度监测、预测和成因分析，核心目标是把多源数据接入、数据治理、预测建模、可视化分析和致浊因子归因诊断整合成一个可用系统。

## 2. 业务背景

水体浊度受悬浮泥沙、降雨径流、潮汐水动力、风速风向、上游来水、工程调度和季节性气象条件共同影响。传统系统通常只能展示数据，不能很好回答下面几个问题：

- 为什么浊度变了
- 未来会怎么变
- 主要致浊因子是什么
- 是否存在自净失效或浊度突增风险

因此，系统需要从“数据展示平台”提升为“预测 + 解释 + 辅助决策平台”。

## 3. 建设目标

### 3.1 数据目标

- 建立多源异构水环境数据接入和标准化管理能力
- 形成可持续更新的多模态水质综合数据库

### 3.2 模型目标

- 构建面向水体浊度的动态预测模型
- 实现目标区域浊度预测值与实测值的对比分析

### 3.3 业务目标

- 提供可视化看板、交互查询、时序趋势分析和站点空间分布展示
- 输出致浊因子诊断结果，辅助解释浑浊形成机制

## 4. 用户对象

- 水环境监测机构
- 科研院所
- 生态环境管理部门
- 水利调度单位
- 从事水质预测、水动力分析和河口浊度研究的技术人员

用户应能通过浏览器完成数据导入、数据检索、图表查看、模型预测、结果对比和诊断报告下载。

## 5. 总体架构

系统采用三层架构：

### 5.1 数据层

负责：

- 多源异构数据接入
- 数据清洗
- 标准化处理
- 统一存储

数据类型包括：

- 水质数据
- 气象数据
- 水文数据
- 水利调度数据
- 站点空间数据

### 5.2 算法层

负责：

- 多模态特征构建
- MSCIM 浊度预测
- 因果诊断
- 知识图谱关联推理
- 模型评估

### 5.3 应用层

负责：

- 可视化看板
- 交互查询
- 预测任务配置
- 预测结果对比
- 诊断报告输出
- 用户权限与系统管理

## 6. 技术路线

主线应为：

1. 数据接入
2. 数据治理
3. 特征融合
4. 模型预测
5. 归因诊断
6. 可视化展示与报告输出

其中最重要的输入处理包括：

- 时间对齐
- 空间匹配
- 单位换算
- 异常检测
- 滞后特征构建
- 多模态特征矩阵生成

## 7. 核心功能模块

## 7.1 多源异构水质数据融合与管理模块

应支持：

- 接口接入、Excel/CSV 导入、数据库同步
- 字段映射
- 数据清洗
- 时间对齐
- 空间匹配
- 入库存储
- 导入日志与异常记录

典型输出：

- 原始数据表
- 标准字段字典
- 清洗后数据集
- 时间对齐数据表
- 站点空间索引
- 综合数据库

## 7.2 水质多维数据可视化与交互模块

应支持：

- 综合看板
- 时间序列分析
- 多指标对比
- 空间分布展示
- 交互查询

典型图形包括：

- 折线图
- 柱状图
- 热力图
- 地图点位
- 指标统计卡片

## 7.3 水体浊度动态预测与模拟模块

应支持：

- 预测任务配置
- 模型加载
- 预测计算
- 预测值与实测值对比
- 结果导出

典型输出包括：

- 预测浊度序列
- 预测-实测对比图
- 误差指标
- Excel/PDF/Word 报告

## 7.4 致浊因子因果诊断与归因分析模块

应支持：

- 因子库管理
- 知识图谱构建
- 因果强度计算
- 主导因子识别
- 诊断报告生成

输出重点不只是“相关性”，而是：

- 哪个因子主导
- 通过什么过程影响
- 在什么时间段最明显

## 8. 数据库与数据处理设计

## 8.1 数据类型

应统一管理以下数据：

- 水质数据：站点编号、采样时间、水温、浊度、pH、电导率、溶解氧、悬浮物浓度等
- 气象数据：降雨量、风速、风向、气温、湿度、气压、太阳辐射等
- 水文数据：流速、流量、水位、潮位、流向、径流量等
- 水利数据：闸门开度、调度时间、排水量、泵站状态等
- 空间数据：站点名称、经纬度、水域名称、行政区、断面类型等

## 8.2 清洗规则

应至少覆盖：

- 字段完整性检查
- 重复记录处理
- 异常值识别
- 单位标准化
- 时间尺度统一
- 空间关系校验

## 8.3 存储方案

推荐采用三类存储：

- 时序库：连续监测序列
- 关系库：用户、站点、任务、模型版本、报告记录
- 图数据库：致浊因子、过程、指标、区域之间的关系

## 9. 算法模型要求

## 9.1 MSCIM 模型

作为系统核心预测模型，应接收：

- 水质状态特征
- 气象驱动特征
- 水文动力特征
- 水利调度特征
- 空间站点特征

并输出：

- 目标区域或站点的浊度预测值

同时，系统应保存：

- 模型版本
- 训练数据范围
- 特征列表
- 参数文件
- 评估结果

## 9.2 模型运行流程

训练模式应支持：

- 训练区间选择
- 验证区间选择
- 自动划分样本
- 参数保存
- 评估指标生成

预测模式应支持：

- 目标站点选择
- 预测时间范围选择
- 模型版本选择
- 结果生成与对比

## 9.3 预测评估

建议保留以下指标：

- MAE
- RMSE
- R²
- MAPE

## 10. 用户与权限

建议至少支持三类角色：

- 管理员：用户管理、数据源配置、模型管理、系统配置、全量数据访问
- 分析人员：数据查询、预测任务创建、可视化分析、报告生成
- 访客用户：查看授权范围内的结果和报告

## 11. 操作流程

### 11.1 数据管理

- 上传数据
- 字段映射
- 启动导入
- 查看成功条数、失败条数和异常清单
- 对错误数据进行标记、修正或删除

### 11.2 可视化查询

- 选择水域、站点、指标和时间范围
- 查看时序曲线、统计卡片和空间地图
- 支持多指标同轴或多轴展示

### 11.3 浊度预测

- 选择区域或站点
- 选择预测时间范围与步长
- 选择模型版本
- 启动预测任务
- 查看预测曲线、实测曲线和误差曲线

### 11.4 诊断报告输出

- 读取预测任务输入因子
- 结合知识图谱和历史相似过程计算因子影响强度
- 输出因子排序、主导过程判断、时间段解释和建议关注指标

## 12. 安全与异常处理

系统应记录：

- 登录日志
- 导入日志
- 查询日志
- 预测任务日志
- 模型调用日志
- 报告生成日志

至少需要处理以下异常：

- 文件格式错误
- 字段缺失
- 数据越界
- 模型调用失败
- 权限不足

## 13. 软件价值

该系统相对于单纯展示平台的提升在于：

- 能融合多模态数据
- 能做动态预测
- 能做结果解释
- 能做归因诊断
- 能输出结构化报告
